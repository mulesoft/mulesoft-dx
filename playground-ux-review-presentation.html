Thursday June 26, 2026

I found an API that looks right. I want to consume it. But first I need to validate it does what I need. And to validate it — I identify an operation, I create a request, I send it, I examine the response. That's all. Everything you're about to see serves that.

But today, to do this, I leave V2. I open Postman, I copy-paste URLs, tokens, IDs. I build my mental model somewhere else. I lose context. That's the problem we're solving.

So — I'm a developer. I arrive at V2, I search for an API, click, I find it, click, I'm inside the API detail. I go straight to the Playground tab. I don't know much yet. And — you remember our current console? Complex, crowded, full of navigation patterns and formats and layers. You'll notice this is simple. I think it's simple because we achieved a simple experience. No complications.

Everything is ready. Something I understand immediately. A list of operations — exactly what I need to identify which one I want to try. And like a comic strip, I find the right order on a single screen, left to right: I identify the operation, I create my request, I send it, I examine the response. Four steps, one screen, no navigation.

I zoom in. I look at the operations. If there are many, I have search and filters. If I don't want to read URLs I can search by name. If I know I want to start with a GET or a POST, I can filter and shrink the list. I clear everything and stay with the first GET.

I want to send a request. And wait — I didn't configure auth. It's already done. The platform knows who I am, my session is active, and the playground uses it. In Postman I'd be pasting tokens, setting up environments, fighting with OAuth flows. Here? Nothing. And if I need a different method — bearer, API key, OAuth2 — I set it once and it persists across all operations. I don't re-authenticate every time I switch.

I don't fill in anything. I just hit Send. Here's my response. I examine it. I know what this operation returns. It gives me what I need — I can validate this API does what I expected. Good. But I don't know this API well. What operation should I try next?

Here, below the response: Next Steps. This is unique. Nobody offers this. Why? Because V2 has context — context that Postman doesn't have. We know the API, the operations, the relationships between them. And we take advantage of it.

I click a Next Step. I want to validate the next operation — and the fields appear pre-filled. Some values come from my previous response. Some come from my session. And some that V2 knows exist somewhere but I haven't tried yet — Discover. So I have three ways to collect data: session values, inferred from responses, and discoverable from related endpoints. I identify, I create, I send, I examine — again and again, fast, almost nothing to type. Each operation validates something new about this API. It all just works.

Now I want to review my history. But wait — I'm focusing here. I want more space to examine responses. I collapse the V2 navbar — more space. I collapse the operation list — even more space. And the panels? I drag the dividers. I want more space for the response because I'm reading a large payload — I drag. I want more space for the request because I'm editing a complex body — I drag. The interface adapts to me. I can concentrate. No scrolling, nothing hidden, everything important stays visible. Easy. Very easy.

But — I don't want to feel like a prisoner of this. I've validated the API, I want to consume it in my project. I press Copy as Code — one click — and I leave with my requests ready to paste into my codebase or into any other tool.

That's the workflow. Identify, create, send, examine. Everything else supports that.
